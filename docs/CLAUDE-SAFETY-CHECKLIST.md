# Claude 使用注意事项与本机防护总清单

状态日期：2026-10-24（America/Chicago）。本清单汇总用户提供的十项指南、两张风控文章截图、历次安装维护要求，以及 GitHub、Google、微信公众号、YouTube、X 的调研。它回答三件事：**已经做了什么、没有做什么及原因、哪些仍要用户自己注意**。

本轮范围由用户明确选择：Claude 专用链路尽量严格；保留普通浏览器、公司内网、其他开发工具及服务器。Chicago、美国地区和英文是用户选择的本地严格基线，不是已公开的封禁判据。账号状态备注按最新要求从主界面、观察函数及读取流程移除，不再读取旧的人工观察；原有`status`协议保持不变。

## 如何读这张清单

| 标记 | 含义 |
|---|---|
| 官方／协议 | 能确认公开规则、接口或技术能力，不能据此推定厂商未公开的风控权重。 |
| 本机实测 | 在列明的本机或隔离场景中验证过，不能外推到所有客户端、所有网络和所有账号。 |
| 社区经验 | 个案、作者逆向或历史版本报告；可作线索，尚不足以形成普适因果或概率。 |
| 用户偏好 | 用户主动选择的严格策略，可以比官方要求更紧，但不包装成官方规定。 |
| 已落实 | 已有实现和相应验证；仍须看同一行的范围限制。 |
| 部分落实／待验 | 已有一部分措施，其他范围尚未核验。 |
| 未实施 | 没有自动执行；原因可能是缺少证据、与既定范围冲突或有明确副作用。 |
| 用户处理 | 工具无法替用户确认的身份、邮箱、付款、实际使用和官方复核事项。 |

代码提交、已安装版本、界面打开、网络传输、登录成功和模型权限是不同层次。主窗口“本地通过”只说明本地检查；灰色范围说明可以保留，不追求全部绿标。

## 先看结论

| 类别 | 当前落实情况 |
|---|---|
| 专用浏览器／原生 CLI | 独立资料或配置目录、固定具体 US 节点的专用 HTTP 入口、真实路由核验、失败不回退通用入口。 |
| 浏览器隐私 | 英文 HTTP 与 JavaScript 信号、Chicago／美国 Intl、限制非代理 UDP、关闭 QUIC／普通扩展／预测，指定权限默认拒绝。 |
| CLI 网络 | 大小写代理变量一致；只允许专用 TCP 端口，其他 TCP／UDP 和子进程直连拒绝；限制启动沙箱外应用的两条通路。 |
| 桌面版 | 启动前严格检查，运行中连续故障或缺证后停止桌面主进程；它有检测窗口，仍不是系统防火墙。 |
| 账号档案 | A/B 两步确认、环境复检、失败不伪报成功、快照与当前标记事务保护；维护测试不切真实 A/B。 |
| 用户习惯 | 邮箱控制权、官方认证、付款、验证提示、注册后何时订阅和正常使用，由用户自己处理。经验门槛没有自动写进检查器。 |

## 一、网络与断链防护

| 注意事项 | 依据等级 | 本机状态 | 实现或验证证据 | 用户仍需注意 |
|---|---|---|---|---|
| 固定出口，避免意外切到另一地址 | 官方能力＋本机实测＋用户偏好 | 已落实 | 单 IP 锁与选择组策略叠加，不能只因地址在已配置列表就接受；[核心](../core/claude-switch.sh)、[路由审计](../core/network-audit.py)。 | 不随意更换最终出口。确需更换时，重新核对固定锁、节点与严格目标，不能只点另一个节点。 |
| TUN 接管不等于所有目标都走同一节点 | 官方能力＋本机实测 | 已落实区分 | 分别检查 Rule、TUN、所选节点、实际 TLS 连接；真实域名与源端口对应控制器记录。 | 看实际连接证据，不能只看 TUN 开关、规则文本或浏览器查 IP。 |
| 专用浏览器的第三方／背景目标也要固定出口 | 本机实测 | 已落实 | 专用 `protected_listener` 仅监听 loopback，直接绑定具体节点；本机默认端口17897，不经通用分流。独立实例在 `MATCH,DIRECT` 下仍走指定节点；上游失效后专用入口失败、普通对照仍通。 | 日常通过专用入口使用；普通代理端口和普通浏览器保留原用途，不自动获得这层约束。 |
| 专用入口不能退回普通代理或 DIRECT | 官方能力＋本机实测＋用户偏好 | 已落实 | 专用入口缺失、节点／IP／国家不符、入站证据不足即拒绝；Edge 单一代理无 DIRECT 后备。 | 失败时先排查，不为了继续用而加 `direct://`、自动直连或任意代理后备。 |
| 节点故障与代理软件退出要分开验证 | 本机实测 | 部分落实／待验 | 已做临时代理停止、CONNECT 拒绝和临时上游失效实验；没有为了验收掐掉真实 Clash。 | 新客户端、切网、休眠唤醒和真实代理退出后应重新核验，不能把一个故障实验当作全部场景。 |
| IPv6 不能只检查 Wi-Fi | 本机实测＋用户偏好 | 已落实 | Wi-Fi 状态与 Clash 内核 IPv6 分别检查；内核未知也不算关闭，订阅末尾脚本维持关闭。 | 网络服务、客户端或配置更新后重扫；改磁盘文件不代表内存已刷新。 |
| DNS Fake-IP 不等于所有上游 DNS 都已验证 | 官方能力＋本机实测 | 部分落实／待验 | 指定域名 Fake-IP 映射检查；专用 HTTP 代理处理目标路径，专用 Profile 关闭自身 DoH。 | 解析器国家不同不自动等于污染；需结合浏览器安全 DNS、系统与代理日志核对，不能只追一个网站的分数。 |
| STUN／WebRTC 不只看一个域名或端口 | 官方能力＋本机实测 | 部分落实／待验 | 四个 STUN 域名及 UDP 3478／5349／19302 优先 REJECT；非代理 UDP 与 QUIC 限制；无响应但无规则证据时不称通过。 | 没有覆盖所有端口、所有 ICE／RTCDataChannel 场景。音视频权限拒绝也不等于完整关闭 WebRTC 栈。 |
| 桌面运行中“无法核验”也应保守处理 | 用户偏好＋本机实测 | 已落实，范围有限 | 非待命的 `warn/fail` 连续两次触发桌面停止，恢复／待命清零；TLS 后 HTTP 失败不会再清零故障。 | 守护只终止桌面主进程，不终止普通浏览器或独立 CLI；周期检测有窗口。 |
| 不把 HTTP 200、TLS 成功或 toast 当完整业务成功 | 协议＋故障案例 | 已落实区分 | 探针要求 HTTP 传输完成，并单独判断路由证据；实际重生成后继续核对端口、出口及普通联网。 | 大文件完整性、WSS、已认证模型调用仍需相应验收；不能据状态码断言账号可用。 |
| 前置机场变更不一定改变最终出口 | 技术机制＋本机配置 | 已按最终出口核验 | 专用入口绑定最终具体节点；前置链单独观察，不因前置名字相同就认定地址未变。 | 可以排查前置链健康，但最终网站看到的地址必须继续符合固定锁。 |
| VPS、iPhone、Mac Air 不能套用本机结果 | 用户范围＋历史案例 | 本轮未迁移／未重新验收 | 本轮不改变服务器、手机或其他 Mac 的网络策略；公共包不含私有代理与登录资料。 | 每台设备独立校验。iPhone 要检查规则模式、GLOBAL 是否误指 DIRECT、Wi-Fi／蜂窝切换；iCloud 同步文件不等于另一台已部署。 |
| 不全局封锁同 UID、整个 Edge 或公司内网 | 用户范围＋官方机制 | 未实施，保留正常用途 | PF 不直接按进程名；浏览器 Profile 不是防火墙身份。同一 Edge 二进制的全局规则会波及普通浏览器。 | 若以后要系统出站过滤，先设计应用／进程树识别、规则及失败验收，再单独授权。 |

## 二、Chicago 信号与专用浏览器

| 注意事项 | 依据等级 | 本机状态 | 实现或验证证据 | 用户仍需注意 |
|---|---|---|---|---|
| Chicago 时区、美国地区、英文首选 | 用户偏好＋本机实测 | 已落实为启动基线 | 系统时区／地区／首选语言不符阻止专用入口；原有时区看门狗保留。 | 它们不证明实际所在地。不要为接受别国节点随意改严格目标。 |

| 浏览器进程自己也使用英文环境 | 本机实测＋用户偏好 | 已落实 | 专用进程显式 `LANG/LC_ALL/LC_CTYPE=en_US.UTF-8`、`TZ=America/Chicago`；不写普通 Edge 全局语言。 | 通过专用启动器进入。普通 Edge 的设置和进程不属于这次保证范围。 |

| UA、硬件、GPS 和指纹浏览器 | 官方能力＋社区经验 | 不伪造，未安装额外指纹浏览器 | 保留默认 UA／真实硬件；不注入假 GPS 或用脚本伪造 navigator 语言。 | 零散覆盖可能增加不一致或独特性，检测站低分不等于 Claude 风控通过。 |
| 关闭预测／预加载、普通扩展及默认第三方 Cookie | 官方能力＋本机实测 | 已落实，保留边界 | 指定预测选项关闭；专用命令限制普通扩展；默认第三方 Cookie 阻断。 | Cookie／StorageAccess 的显式例外保留，不称为所有第三方 Cookie 绝对阻断；预测关闭不是全部后台网络总开关。 |

## 四、邮箱、注册、订阅与日常使用：需要用户自己注意

下表专门保留用户要求收录的保守经验。**“未自动执行”不是漏做**：有些事项只能由用户决定，有些没有足够证据成为强制门槛。

| 注意事项 | 依据等级 | 本机状态 | 为什么这样处理 | 用户可执行的注意事项 |
|---|---|---|---|---|
| 邮箱必须由本人控制，恢复方式也在本人手里 | 官方账号安全原则 | 用户处理 | 工具不能验证邮箱卖方是否保留恢复权。 | 用本人可持续访问的邮箱，保护恢复入口和验证码，不借用卖方仍可恢复的账号。 |

## 用户的日常操作清单

1. 通过预期的专用浏览器／原生入口使用，检查当前档案与实际登录身份；需要桌面切号时先选A/B再确认。
2. 看到红色故障先停止，读完整说明并重新扫描；灰色项按其覆盖范围理解，不为追绿手工消除证据。
3. 不随意换最终出口或增加DIRECT后备；更新Clash、换网络、休眠唤醒或换设备后重新核验。
4. 控制邮箱、恢复方式和凭据；登录邮件进入正确浏览器，付款与验证走正式渠道。
5. 若你选择“新号等约一周再订阅”，将其记作个人保守观察期，正常使用，不刷互动，也不把等满天数当资格验证。
6. 出现限额看用量；出现验证读流程；出现on hold去官方详情请求复核，分别记录时间与错误，不重复清缓存／换号碰运气。
7. 严格权限导致语音、视频、自动开浏览器或工具直连失败时，先分清是本地限制还是服务端错误；任何临时放行都应明确范围并在结束后复核。
8. 不把代理配置、控制器密钥、Cookie、令牌、账号备份、真实邮箱和完整私有日志提交到GitHub或发给不可信教程服务。

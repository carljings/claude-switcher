# 检查分级、路由证据与桌面运行监测

用户已确认本轮修改、重新打包并更新本机。沿用当前工作树及此前功能，不修改账号存档、代理分流、出口策略和现有系统偏好，不提交或推送用户私有配置。

## 方案

保留14项界面与现有切换流程。按用户后续要求采用严格基线：时区、区域格式、客户端英文语言不符继续阻止启动。这是用户选择的本地策略，不是官方封禁条件；网络修复不自动改写或放宽这些设置，显式地区设置入口保留。DNS项说明所检测的域名映射，STUN项统一使用同一判断函数，修复路径也不把无响应解释成零泄漏。

新增一个仅用Python标准库的网络核验模块，供用户态检查和root所有的守护脚本共用。使用已有私有出口策略读取控制器，不创建新凭据。对Claude网页和API建立无认证TLS探测连接，在连接仍存在时读取控制器中该源端口的规则及代理链；与选择组当前节点核对。真实应用连接另行列示，没有观察到应用连接时明确说明。探测失败、控制器不可读和路由不符分别呈现，不把Fake-IP当成指定代理路由的证据。

保镖仍为进程级保护：只有Claude桌面主进程运行时才检查，核验明确配置的所选出口与API探测链路。连续两次失败后只终止该桌面进程；状态只写root所有的安装目录，不把root执行入口留在用户可写目录。未配置控制器时不伪称完整保护。界面展示上次监测时间与范围，不因服务仅注册就报告实时出口保护通过。

采用上述最小共享模块，避免在Shell的检查、修复和守护分支分别复制网络判断。系统防火墙、浏览器/CLI进程终止、自动换节点与iOS客户端不在范围内。

## 验收

1. 隔离HOME回归：时区/地区/语言不匹配仍阻挡；固定出口或真实路由不符仍阻挡；原有诊断、HTTP分类和人工确认机制保留。
2. 模拟控制器及隔离代理：正确链路可核对，DIRECT/其他最终节点会失败；无实际连接只报告探测范围；所有异常输出不泄露控制器凭据。
3. 守护测试：连续两次失败才终止目标；恢复清除失败计数；无桌面进程不探测、不终止其他进程；监测缺失或过期明确说明。
4. Shell语法、Python测试、Swift编译、SHA256清单、App签名和压缩包校验通过后，备份并替换本机App和核心；守护更新在完整候选就绪后一次管理员授权完成。
5. 部署后核对文件哈希、版本、实际检测输出、守护注册路径与权限；原账号文件、Clash配置、选择节点和VPS保持原状。不自动登录账号，不对正式网络进行故障注入。

## 重新扫描

主界面常驻“重新扫描”按钮与扫描时间，支持Command-R；扫描、修复或切换过程中禁用重复发起。每次重置14项状态，只接收本次输出；输出为空或缺少项目时显示失败，不回退上次磁盘结果。重扫不切换账号、不修改网络配置。扫描结束后的按钮始终可用。

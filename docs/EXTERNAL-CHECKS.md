# 外部检测

版本20261024.10按用户最新要求将两个检测入口和用途说明平铺在主界面，点击对应入口即可通过同一个专用Edge打开网页。无需进入二级弹窗。

| 站点 | 重点查看 | 固定入口 |
|---|---|---|
| IPPure：浏览器环境 | 时区、语言、字体、WebRTC、DNS及站点展示的出口信息 | [IPPure](https://ippure.com/claude) |
| Ping0：出口IP | 位置、ASN、IP类型、风险标签和共享人数估算 | [Ping0](https://ping0.cc/ip/) |

IPPure的公开页面介绍了上述浏览器及网络检查。[来源](https://ippure.com/claude)。Ping0说明“家庭宽带”标签仍可包含其他非IDC用途，共享人数是估算值，位置判断也可能有误差；不要把标签视作独享或精确位置证明。[来源](https://ping0.cc/ip/faq)。

## 怎么用

1. 在主窗口下方直接点击IPPure或Ping0检测入口。
2. 等待专用链路预检；失败时按主窗口错误核对，不使用普通浏览器代替这次专用环境检测。
3. 在网页运行或刷新检测，查看具体异常和检测时间。不要把两站不同量纲的评分相加。

软件只打开两个固定HTTPS地址，不自动抓分、填IP、上传报告或保存账号备注。打开后网站会看到该次访问的出口，并可收集页面可用的浏览器特征；手动触发后再发生访问，没有后台轮询。

历史验收：20261024.8安装字体过滤后，用户手工确认专用Edge的IPPure字体项0分、总分2分。它是当时结果，不是当前实时得分，也不是Claude账号权限证明。字体组件仅匹配原有Claude/IPPure范围，新增Ping0入口没有扩大字体过滤范围。

## 技术边界

命令为`claude-switch.sh protected-browser ippure`和`claude-switch.sh protected-browser ping0`；无附加参数仍打开Claude。helper仅允许两个固定ID，不接受任意URL或额外参数。每次打开继续执行严格基线、固定出口、实际目标路由、受管策略、组件完整性、旧进程和资料偏好核对。

没有改变14项本地检查及其判定，没有替代全部DNS/WebRTC路径实测。网页载入失败与本地预检失败分别处理；“已请求打开”不表示已读取网页结果。

设计及验收项见[设计文档](plans/2026-10-24-external-checks-design.md)。
